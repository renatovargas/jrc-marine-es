Fish provisioning: annotated R processing routine

Introduction

This page documents the R routine that turns the Scientific, Technical and Economic Committee for Fisheries (STECF) extraction (Scientific, Technical and Economic Committee for Fisheries, 2024) into the fish provisioning accounts. Fish provisioning is the ecosystem contribution to the growth of aquatic biomass captured in uncultivated production contexts (Haines-Young & Potschin, 2018), and it is valued here with the resource rent approach of the SEEA Central Framework (United Nations et al., 2014). The accompanying methods report states the equations; this page restates the earlier working script in a compact, reproducible form so that the team can inspect each step, reproduce it from the repository alone, and reuse the parts that generalise.

The routine reads two committed RDS files produced from the STECF fleet-segment workbook: FS_data_2008-2024.RDS for income and expenditure, and FS_landings_FAO_2008-2024.RDS for landings in kilograms and euro. Kilograms exist only in the landings file; income and expenditure exist only in FS data. The conversion is documented on the STECF Fleet Segment Data page.

Years 2002 to 2007 come from a second, older source: the 2011 Data Collection Framework (DCF) data call, supplied by JRC in October 2026 as data/dcf/DCF_2011_fleet_economic_and_landings_2002-2010.xlsx. That workbook has a different fleet definition and a different economic variable, so it is prepared in its own section, Extending the series back to 2002, and joins the pipeline just before the allocation.

The routine has three components, and they run in this order because the second depends on the first:

  1. the economic component, which reduces the STECF economic variables to a single net economic result per fleet segment and year (Eq. 3 of the methods report);
  2. the biophysical component, which cleans the landings table, harmonises fishing sub-regions, assigns each sub-region to a European sea region, and attaches the species typology;
  3. the resource rent allocation, which distributes each fleet’s net economic result across the sub-regions and species it landed, then fills the gaps left by fleets without usable economic data.
Important2024 is excluded from the valuation

The STECF files run to 2024, but no Member State has reported a usable expenditure series for that year. The latest fully valuable year is 2023. The two year filters below therefore keep year <= reference_year and drop 2024. Landings for 2024 can be shown in physical terms with a provisional caveat; they cannot carry a resource rent.

NoteMonetary values are 2010 euro

Allocation is done in nominal euro. A single step at the end converts resource rent to constant 2010 prices with Eurostat HICP for EU-27 (Eurostat, 2026). The base year is base_year in the parameters chunk (set to 2010 after consultation with JRC); changing it does not touch the allocation. Tables report both nominal and 2010 euro. Physical landings are not deflated.

NotePaths are relative to the project root

_quarto.yml sets execute-dir: project, so every path below resolves from the repository root regardless of where the .qmd file sits. There is no need for here::here() or setwd().

Sea region assignment

The rules are a direct transcription of the original case_when(); wrapping them in a function means the same classification can be reused by the overuse and blue carbon routines without copying the list of codes again.

assign_sea_region <- function(sub_reg_clean) {
  case_when(
    sub_reg_clean == "0" ~ "unknown",
    sub_reg_clean %in% c("sa28", "sa29", "sa30") ~ "Black Sea",
    sub_reg_clean %in% paste0("sa", 1:27) ~ "Mediterranean Sea",
    str_detect(sub_reg_clean, fixed("27.3.d")) ~ "Baltic Sea",
    str_detect(sub_reg_clean, fixed("27.8")) |
      sub_reg_clean %in% neao_sub_regions ~ "NEAO",
    .default = "ROW"
  )
}

Species typology

STECF identifies species by their FAO ASFIS code but says nothing about what kind of animal it is or where in the water column it lives. The methods report fills that gap from FishBase and SeaLifeBase (Froese & Pauly, 2024; Palomares & Pauly, 2024), and the result is the classification workbook already in data/lookup. We derive two attributes from it: species_group, which separates fish from shellfish and from species whose code could not be matched with confidence, and fish_type, the aggregated water column typology of Table 1 of the methods report. Those names match the nested columns of methods Tables 4 to 13. The workbook column Type holds the water-column codes (benthic, benthopelagic, demersal, pelagic); the fish / shellfish / other split comes from the binary flags. There is no Type_1 column in the lookup.

species_types_raw <- read_excel(species_lookup_file, sheet = "Classification")

species_types <- species_types_raw |>
  transmute(
    species_code,
    species_name_lookup = species_name,
    fish_type = Type,
    species_group = case_when(
      fish == 1 ~ "fish",
      shellfish == 1 ~ "shellfish",
      .default = "other"
    )
  ) |>
  distinct(species_code, .keep_all = TRUE)

Helper functions

These operations recur often enough to be worth naming. Everything else stays as an explicit pipeline, because a named function that is called once hides more than it saves.

Both STECF sheets carry the same block of administrative columns that the assessment never uses. any_of() rather than all_of() means the function works on both sheets even though they do not carry exactly the same set.

drop_stecf_admin_columns <- function(data) {
  data |>
    select(-any_of(c(
      "upload_date", "geo_indicator", "cluster_name", "fromtable",
      "framework", "template_name", "gear", "fishery", "activity"
    )))
}

Harmonising sub-regions is two steps: strip the stray whitespace that STECF sometimes carries, then apply the recode table. We strip first so that a code entered as 27.2.a.1 still matches. The raw sub_reg is kept alongside sub_reg_clean for traceability.

harmonise_sub_reg <- function(data, recodes = sub_reg_recodes) {
  data |>
    mutate(sub_reg_clean = str_remove_all(sub_reg, "\\s")) |>
    left_join(
      recodes,
      by = join_by(sub_reg_clean == from),
      relationship = "many-to-one"
    ) |>
    mutate(sub_reg_clean = coalesce(to, sub_reg_clean)) |>
    select(-to)
}

The gap filling described in Box 2 of the methods report is the same operation applied three times at successively coarser levels of aggregation. Expressing it once as a function that takes the grouping columns as an argument removes about sixty lines of copied code and guarantees that the three passes stay consistent with each other.

# Mean observed price of a species over an arbitrary set of grouping columns.
average_price <- function(reference, by) {
  reference |>
    summarise(price = mean(price, na.rm = TRUE), .by = all_of(by))
}

# Assign that mean price to records that have landings but no usable rent.
# Records that still find no reference price keep a price of zero and are
# passed on to the next, coarser pass.
fill_price_gaps <- function(gaps, reference, by, basis) {
  gaps |>
    select(-any_of(c("price", "sum_revenue", "price_basis"))) |>
    left_join(
      average_price(reference, by),
      by = by,
      relationship = "many-to-one"
    ) |>
    mutate(
      price = replace_na(price, 0),
      price_basis = if_else(price > 0, basis, NA_character_),
      sum_revenue = sum_landed * price
    )
}

Economic component

Loading the STECF economic table

The economic file reports one row per fleet segment, year and economic variable. Inactive fleets are removed first because they land nothing and would otherwise distort the fleet averages. The year filter keeps the panel through reference_year and drops 2024, which cannot be valued.

stecf_economic <- readRDS(stecf_economic_file) |>
  filter(fishing_tech != "INACTIVE", year <= reference_year) |>
  drop_stecf_admin_columns()

Net economic result by fleet

The resource rent approach values the service as the economic surplus of the fleet, that is total income less total costs (Eq. 3 of the methods report). STECF splits its economic variables into groups; we keep only Expenditure and Income, sign the expenditure negatively so that both can be summed in a single column, and aggregate to one net result per fleet segment and year.

Missing values become zero and zero rows are then dropped. That looks circular, and it is deliberate: STECF uses a blank to mean “not reported” and the assessment treats a non-reported item as absent rather than as a true zero, so both end up excluded from the sum.

net_economic_by_fleet <- function(data) {
  data |>
    filter(variable_group %in% c("Expenditure", "Income")) |>
    mutate(value = replace_na(value, 0)) |>
    filter(value != 0) |>
    mutate(money = if_else(variable_group == "Expenditure", -value, value)) |>
    summarise(
      total_expenditure = sum(money[variable_group == "Expenditure"]),
      total_income = sum(money[variable_group == "Income"]),
      total_net = total_income + total_expenditure,
      .by = c(year, fs_name)
    )
}

fleet_net <- net_economic_by_fleet(stecf_economic)

An ecosystem service cannot have a negative flow, because that would describe a disservice. Box 2 of the methods report therefore splits the fleets in two: those with a positive net result carry the valuation, and those with a negative or zero result are treated as missing and recovered later from average prices.

fleet_net_positive <- fleet_net |>
  filter(total_net > 0)

Biophysical component

Loading and cleaning landings

The landings file reports quantities in several units. Only kilograms are relevant here, and rows with a zero quantity carry no information. We rename value to landed_kg immediately, because three different quantities are called value at various points of the original script and the name stops carrying meaning. The same year <= reference_year bound used on the economic file keeps the two sides of the join on the same years.

landings_raw <- readRDS(stecf_landings_file) |>
  filter(year <= reference_year) |>
  drop_stecf_admin_columns() |>
  filter(unit == "kg", value != 0) |>
  rename(landed_kg = value)

Harmonising regions and attaching the typology

Sub-region harmonisation, sea region assignment and the species join all happen in one pipeline. The species join is the step that was previously done by hand in Excel; relationship = "many-to-one" makes dplyr fail loudly if the lookup ever regains duplicate codes, which is the guard the manual workflow lacked.

landings <- landings_raw |>
  harmonise_sub_reg() |>
  mutate(Sea_reg = assign_sea_region(sub_reg_clean)) |>
  left_join(
    species_types,
    by = join_by(species_code),
    relationship = "many-to-one"
  )

Three checks are worth running every time the extraction is refreshed. The first lists species codes present in the landings but absent from the classification workbook; those rows would otherwise reach the accounting tables with a missing fish type. The second compares the species name STECF reports against the name the classification workbook holds for the same code, which is how a mis-assigned code shows itself. The third lists sub-regions that fell through to ROW, the catch-all category and therefore the place where a new or misspelled STECF code will hide.

Extending the series back to 2002

The STECF 2025 data call starts in 2008. In October 2026 JRC supplied the landings and economic tables of the 2011 DCF data call, which cover 2002 to 2010, together with a short description by Domenico. The workbook and the description are kept in data/dcf/. This section prepares those tables so that they look like the STECF tables to the allocation, which then runs once over the whole 2002 to 2023 panel with no change to its logic.

Only 2002 to 2007 are taken from the 2011 call. From 2008 onward the STECF 2025 call stays the source, for three reasons. It is a later revision of the same years. Its coverage is wider, as the overlap check below shows. Keeping it means the published 2008 to 2023 results do not move. The 2011 workbook does contain 2010, but its economic sheet holds almost nothing for that year and its own notes flag 2010 as provisional.

ImportantWhat differs in the 2011 data call
  • No fleet segment code. Following Domenico’s description, a fleet is the landing country plus the vessel length class, for example POL VL1224. This is coarser than the STECF fs_name, which also carries gear and supra-region.
  • Operating cash flow is the net economic result. The 2011 call has no separate income and expenditure items before 2008, so Eq. 3 is replaced by the reported operating cash flow (OCF), as Domenico instructed. OCF does not deduct consumption of fixed capital or unpaid labour, which the STECF Expenditure group does. Rent for 2002 to 2007 is therefore higher than a like-for-like measure would give; the overlap check below sizes the gap.
  • Coarser fishing areas. Much of the catch is reported at FAO area level (27.7, 27.4, 27.3) rather than at division level, and the Mediterranean is reported in FAO divisions (37.1.2, 37.2.1) rather than GFCM sub-areas. Supply tables for those years have coarser rows, and the division map covers less of the catch.
  • United Kingdom. The 2011 call includes the United Kingdom; the STECF 2025 call does not. Its landings and fleets are dropped so that every year covers the same Member States.
  • Small segments. The workbook notes say that segments of fewer than 10 vessels are excluded.

Landings

Landed weight is totwghtlandg, in kilograms. The unit is confirmed against STECF 2025: for Finland and Latvia in 2008 the two calls agree to the kilogram. Rows with a zero or negative weight are removed. The seven negative weights in the workbook all fall in 2008 and 2009, outside the years used. Sub-region codes are upper case in this workbook (27.9.A), so they are lowered before the shared whitespace strip and recode.

Two groups of rows are removed from the recode table for this source. The four rows that turn FAO Mediterranean divisions into GFCM sub-areas are removed because the 2011 call reports the whole Mediterranean in FAO divisions; recoding three divisions to single sub-areas while the others stay as divisions would mix two systems in one year. The 27.8 to 27.8.a row is removed because in the 2011 call 27.8 is the main reporting code for the Bay of Biscay, about 180,000 tonnes a year; in STECF 2025 it is a residual of a few tonnes.

sub_reg_recodes_dcf <- sub_reg_recodes |>
  filter(!str_starts(from, fixed("37.")), from != "27.8")

assign_sea_region() recognises fine division codes only, so it would send the coarse codes of the 2011 call to ROW. The rule below assigns by FAO major area instead. Area 27 is NEAO, except its Baltic part. Area 37 is the Mediterranean, except subarea 37.4, which is the Black Sea. 27.3 covers both the Baltic and the Skagerrak and Kattegat; in this workbook it is reported by Poland, Latvia, Estonia and Lithuania, almost all of it sprat, herring and cod, so it is assigned to the Baltic Sea.

assign_sea_region_dcf <- function(sub_reg_clean) {
  case_when(
    sub_reg_clean %in% c("0", "0.0") ~ "unknown",
    sub_reg_clean == "27.3" |
      str_starts(sub_reg_clean, fixed("27.3.d")) ~ "Baltic Sea",
    str_detect(sub_reg_clean, "^27(\\.|$)") ~ "NEAO",
    str_starts(sub_reg_clean, fixed("37.4")) ~ "Black Sea",
    str_detect(sub_reg_clean, "^37(\\.|$)") ~ "Mediterranean Sea",
    .default = "ROW"
  )
}

Distributing the net result

A fleet earns one net result but fishes several sub-regions and several species, and STECF cannot attribute cost or revenue any more finely than the fleet. The assessment therefore distributes the net result in proportion to the quantities landed, in two nested steps: first across the sub-regions the fleet worked (Eq. 4 and Eq. 5), then across the species it landed in each of those sub-regions (Eq. 6 and Eq. 7).

The original script carried these weights as percentages and divided by one hundred again at each use. We keep them as shares, which is arithmetically identical and removes four opportunities for a misplaced factor of one hundred.

landings_valued <- landings_valued_input |>
  mutate(
    fleet_landed_kg = sum(landed_kg, na.rm = TRUE),
    .by = c(year, fs_name)
  ) |>
  mutate(
    fleet_area_landed_kg = sum(landed_kg, na.rm = TRUE),
    .by = c(year, fs_name, sub_reg_clean)
  ) |>
  mutate(
    # Eq. 4: share of the fleet's catch taken in this sub-region
    share_fleet_area = fleet_area_landed_kg / fleet_landed_kg,
    # Eq. 5: net result attributable to the fleet in this sub-region
    net_fleet_area = total_net * share_fleet_area,
    # Eq. 6: share of that sub-regional catch made up by this species
    share_species_area = landed_kg / fleet_area_landed_kg,
    # Eq. 7: net result attributable to the species in this sub-region
    net_species = net_fleet_area * share_species_area
  )

Observed prices

The accounts report one figure per species, landing country and sub-region, so the fleet dimension is aggregated away here. Dividing the summed net result by the summed quantity gives the implied resource rent per kilogram, which is the price used to value the gap records in the next section.

accounting_keys <- c(
  "year", "country_code", "sub_reg_clean", "Sea_reg",
  "species_code", "species_name", "species_group", "fish_type"
)

rent_prices <- landings_valued |>
  summarise(
    sum_landed = sum(landed_kg, na.rm = TRUE),
    sum_revenue = sum(net_species, na.rm = TRUE),
    .by = all_of(accounting_keys)
  ) |>
  mutate(
    price = if_else(sum_landed > 0, sum_revenue / sum_landed, NA_real_),
    price_basis = "observed rent"
  )
NoteTwo deliberate differences from the original script

The original produced this table with mutate() followed by distinct(), which left one row per underlying fleet record rather than one row per accounting key; because the raw sub_reg was among the columns kept, sub-regions that had been collapsed by the recode table survived as separate rows carrying the same group total, and the final aggregation added them together. Using summarise() over an explicit key list produces exactly one row per group and removes that double counting.

The original also guarded the division against a zero in the individual record’s own net value rather than in the group’s total quantity, which set a price to NA for records that had a valid group price. The guard here is on sum_landed, which is the quantity actually in the denominator.

Filling the gaps

Box 2 of the methods report fills the gaps in three passes, each one coarser than the last: the average price of the species in the same country, then in the same sub-region, then across Europe. Each pass keeps what it could value and hands the remainder to the next. Anything still unvalued after the third pass has no observed price anywhere in the dataset for that species.

The four sources are aggregated once more onto the accounting keys, because a species, country and sub-region combination can receive quantities from both a positive-rent fleet and a gap-filled fleet. The final price is the revenue-weighted average that results, and the report’s units are tonnes and thousands of euro.

price_basis is collapsed into a readable label rather than dropped, so each row of the published table carries the provenance of its own valuation. data_source does the same for the data call each year comes from.   other_not_identified = "Not identified",
  Total = "Total"
)

prepare_sut_types <- function(data) {
  data |>
    mutate(
      species_group = case_when(
        species_group == "fish" ~ "fish",
        species_group == "shellfish" ~ "shellfish",
        .default = "other"
      ),
      fish_type = case_when(
        species_group == "other" ~ "not_identified",
        is.na(fish_type) ~ "not_identified",
        .default = fish_type
      ),
      species_group = factor(species_group, c("fish", "shellfish", "other")),
      fish_type = factor(
        fish_type,
        c("benthic", "benthopelagic", "demersal", "pelagic", "not_identified")
      )
    )
}

nested_sut <- function(data, row_var, value_var) {
  wide <- data |>
    prepare_sut_types() |>
    summarise(
      value = sum(.data[[value_var]], na.rm = TRUE),
      .by = all_of(c(row_var, "species_group", "fish_type"))
    ) |>
    pivot_wider(
      names_from = c(species_group, fish_type),
      values_from = value,
      names_sep = "_",
      values_fill = 0,
      names_expand = TRUE
    )

  missing_cols <- setdiff(sut_value_cols, names(wide))
  for (col in missing_cols) {
    wide[[col]] <- 0
  }

  wide |>
    mutate(Total = rowSums(across(all_of(sut_value_cols)), na.rm = TRUE)) |>
    filter(Total != 0) |>
    select(all_of(row_var), all_of(sut_value_cols), Total) |>
    arrange(across(all_of(row_var)))
}

add_total_row <- function(tbl, row_var) {
  totals <- tbl |>
    summarise(across(where(is.numeric), \(x) sum(x, na.rm = TRUE))) |>
    mutate(!!row_var := "Total", .before = 1)
  bind_rows(tbl, totals)
}

sea_sut <- function(year, sea, side, value_var, data = fish_provisioning) {
  slice <- data |> filter(year == .env$year, Sea_reg == .env$sea)
  if (side == "supply") {
    nested_sut(slice, "sub_reg_clean", value_var) |>
      add_total_row("sub_reg_clean") |>
      rename(EEZ = sub_reg_clean)
  } else {
    slice |>
      left_join(country_names, by = "country_code") |>
      mutate(country = coalesce(country, country_code)) |>
      nested_sut("country", value_var) |>
      add_total_row("country") |>
      rename(Country = country)
  }
}

europe_supply_sut <- function(year, value_var, data = fish_provisioning) {

europe_region_table <- function(year, value_var) {
  by_sea <- fish_provisioning |>
    filter(year == .env$year) |>
    summarise(value = sum(.data[[value_var]], na.rm = TRUE), .by = Sea_reg) |>
    mutate(Sea_reg = factor(Sea_reg, levels = sea_order)) |>
    complete(Sea_reg, fill = list(value = 0)) |>
    arrange(Sea_reg) |>
    mutate(Sea_reg = as.character(Sea_reg))
  supply <- by_sea |>
    pivot_wider(names_from = Sea_reg, values_from = value) |>
    mutate(Total = rowSums(across(everything()), na.rm = TRUE)) |>

    mutate(SUT = "Use") |>
    mutate(across(-c(SUT, Total), \(v) NA_real_))
  bind_rows(supply, use)
}

write_banner_block <- function(wb, sheet, start_row, n_cols, title, year, grain) {

write_data_block <- function(wb, sheet, data, data_start) {

}

Joining results to the marine regions

Geometry lives in data/gisdata/marine_regions.gpkg and stays static. The published GeoPackage holds one copy of each polygon, with one column per year for landings, resource rent and price. Species, country and fleet belong in the RDS and Excel files, not in the geometry. Duplicating the polygons once per year was what made the first export large; three separate files, one per metric, would triplicate the geometry for no gain. QGIS users style tonnes_2023, rent_const_k_eur_2018 or price_const_eur_kg_2023 on the same layer. Nominal rent and price columns are kept beside the constant-price ones.

Two layers are published. The macro layer is the four pan-European sea regions; it joins on Sea_name after a label recode. The division layer is the 58 FAO divisions and subdivisions; it joins on F_CODE, or on F_DIVISION when that code is unique to one feature, which is how the collapsed NEAO recodes find the dissolved polygons. Price is the quantity-weighted average, revenue over live weight, not a sum of prices.

There is no legal-EEZ layer. marine_regions.gpkg is FAO fishing-area geometry only, and fish_provisioning.gpkg therefore has the same two result layers. Methods Tables 10 to 13 label FAO/GFCM sub_reg_clean as EEZ on the supply tables; that is the spatial unit of supply, not a coastal-state exclusive economic zone. Landing-country tables use STECF country_code (Eq. 2) and must not be drawn as if they were EEZs: the Member State of landing is not the coastal state of the fishing ground. Maps stay on the FAO layers.

Mediterranean accounts use GFCM sub-areas (sa1 to sa27) while the geometry is FAO 37.x.x, so the GSA lookup is applied before the join. Black Sea sub-areas sa28 to sa30 are not in that workbook; they are mapped to Marmara, the Black Sea and the Azov Sea following the GFCM numbering. ROW cannot appear on a European map. In 2023 it was 21 percent of tonnage, so any map needs that reconciliation in mind. Legacy result columns on the source layers (Tonnes_23, Money_23 and the truncated overuse names) are not copied.

wide_metrics <- function(data, id_cols) {
  widen <- function(value_col, prefix) {
    data |>
      select(all_of(id_cols), year, all_of(value_col)) |>
      pivot_wider(
        names_from = year,
        values_from = all_of(value_col),
        names_prefix = prefix
      )
  }
  widen("landed_tonnes", "tonnes_") |>
    left_join(widen("revenue_thousand_eur", "rent_k_eur_"), by = id_cols) |>
    left_join(widen("revenue_thousand_eur_constant", "rent_const_k_eur_"), by = id_cols) |>
    left_join(widen("price_eur_per_kg", "price_eur_kg_"), by = id_cols) |>
    left_join(widen("price_eur_per_kg_constant", "price_const_eur_kg_"), by = id_cols) |>

      all_of(id_cols),
      all_of(paste0("tonnes_", panel_years)),

Decisions from JRC (September 2026)

Domenico’s answers to the open points, and what the routine now does.

  • Base year. Constant prices use 2010 (base_year in the parameters chunk). Change that one line and re-render to switch; do not fold a new deflator into the allocation.
  • Subsidies on investments. Operating subsidies (totdirsub) sit inside variable_group == "Income", so the Income plus Expenditure filter already captures them. Subsidies on investments (subinvest) sit under Capital and remain excluded. Box 1 of the methods report will be corrected so that it no longer appears to include them.
  • Type and Type_1. The published tables nest species group (fish / shellfish / other) with fish type (benthic, benthopelagic, demersal, pelagic). That is our species_group and fish_type. In the classification workbook, Type is the water-column typology; the fish / shellfish split is the binary flags. There is no Type_1 column. The original-script names were the other way around relative to Domenico’s note; the table columns are what we match.
  • Duplicate species codes. The eight duplicated codes are identical pairs. They are dropped with distinct().
  • Mediterranean sub-areas sa11.1 and sa11.2. Recoded to sa11 and counted in the Mediterranean. The 2023 shapefile tonne anchors for Mediterranean and ROW therefore shift by that tonnage.
  • EEZ. STECF has no coastal-state EEZ field. Supply tables label sub_reg_clean as EEZ, with a note that these are FAO/GFCM fishing areas. Maps stay on FAO layers. Use tables are landing country.
  • Overuse. Wired after allocation from the 2018 FSI scores. It is a companion overlay, not a column of the official SUT. Scores are held constant across years until a new stock-assessment vintage arrives.
  • 2002 to 2007 (October 2026). Added from the 2011 DCF data call, with fleets defined as country plus vessel length and operating cash flow as the net result, following Domenico’s description of the dataset. See Extending the series back to 2002.
